# SOC Alert Automation with n8n

## Overview

This section documents the alert automation layer implemented in the Mini SOC Monitoring Lab.

The goal of the automation is to extend the Splunk detection workflow beyond alert generation by automatically forwarding selected security alerts to an external notification channel for faster analyst awareness.

The automation was implemented using **n8n** as the orchestration platform.

## Automation Architecture

The implemented workflow follows this path:

```text
Linux Victim
     |
     v
Linux Authentication Logs
     |
     v
Splunk Universal Forwarder
     |
     v
Splunk Enterprise
     |
     v
Scheduled Detection Alert
     |
     v
Splunk Webhook Alert Action
     |
     v
n8n Webhook
     |
     v
Duplicate Filtering
     |
     v
Telegram Bot
     |
     v
SOC Analyst Notification
```

## Components

| Component | Purpose |
|---|---|
| Splunk Enterprise | SIEM, detection logic, scheduled alerts |
| Splunk Universal Forwarder | Sends monitored Linux logs to Splunk |
| n8n | Security automation and workflow orchestration |
| Webhook | Transfers alert data from Splunk to n8n |
| Duplicate Filtering | Prevents repeated processing of duplicate alerts |
| Telegram Bot | Delivers the final SOC notification |
| Docker | Runs the n8n service inside the lab environment |

## Automation Objective

The automation was designed to:

- Receive security alerts generated by Splunk.
- Forward alert information automatically to n8n.
- Process the incoming alert payload.
- Reduce duplicate notifications.
- Format the alert into a readable SOC notification.
- Deliver the notification to Telegram.
- Reduce the need for continuous manual monitoring of the Splunk interface.

## Current Workflow

The first validated automation workflow is connected to the:

**SSH Brute-Force Detection**

When the Splunk detection triggers, the alert is forwarded to n8n through a webhook.

n8n processes the event and sends a structured SOC notification to Telegram.

## Security Considerations

Sensitive information must never be committed to the repository.

The following values are excluded from screenshots, documentation, and exported workflows:

- Telegram bot tokens
- API credentials
- Authentication secrets
- Session cookies
- Private webhook secrets
- Passwords

Credentials are stored only inside the local n8n credential store.

The automation successfully extends the Mini SOC workflow from:

```text

```

to:

```text
Detection → Alert → Automation → Analyst Notification
```

This provides a practical example of basic **SOAR-style security automation** integrated with a SIEM.
